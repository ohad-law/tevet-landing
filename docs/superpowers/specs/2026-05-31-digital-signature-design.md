# חתימה דיגיטלית מרחוק — מסמך עיצוב

**תאריך:** 31.05.2026  
**פרויקט:** CRM משרד עו"ד טבת  
**סטטוס:** מאושר — ממתין לפיתוח

---

## מטרה

בניית מערכת חתימה דיגיטלית מרחוק מובנית ב-CRM. עורך הדין שולח מסמך (ייפוי כח, הסכם שכ"ט, תצהיר) ללקוח → הלקוח חותם מהנייד/מחשב → המסמך החתום מתוייק אוטומטית בתיק.

**ללא ספקים חיצוניים.** הכל בנוי פנימית.

---

## גישה טכנית: שדות חתימה ממוקמים

עורך הדין גורר שדות חתימה על גבי תצוגת ה-PDF בדיוק לאיפה שצריך. הקואורדינטות נשמרות כאחוזים מגודל העמוד. כשהלקוח חותם — `pdf-lib` ממיר לנקודות PDF ומטביע בדיוק באותו מקום, בכל מסמך, בכל מכשיר.

## ארכיטקטורה

### טבלת DB חדשה: `signature_requests`

```sql
create table signature_requests (
  id            uuid primary key default uuid_generate_v4(),
  case_id       uuid references cases(id) on delete cascade,
  client_id     uuid references clients(id),
  document_name text not null,
  original_url  text not null,        -- PDF מקורי ב-Supabase Storage
  signed_url    text,                 -- PDF חתום (ממולא אחרי חתימה)
  token         text unique not null, -- טוקן סודי בקישור ללקוח
  status        text not null default 'pending'
                check (status in ('pending','signed','expired')),
  signature_fields jsonb default '[]', -- [{type, page, x, y, w, h} כ-%]
  signer_name   text,
  signer_ip     text,
  signer_device text,
  signed_at     timestamptz,
  expires_at    timestamptz not null, -- 30 יום מיצירה
  created_at    timestamptz default now()
);
```

### Supabase Storage bucket: `signed-documents` (פרטי)

### דפים חדשים

| נתיב | גישה | תיאור |
|---|---|---|
| `/crm/signatures` | פנימי | רשימת כל בקשות החתימה |
| `/crm/cases/[id]` | פנימי | כפתור "שלח לחתימה" + מודאל |
| `/sign/[token]` | ציבורי | דף החתימה ללקוח (ללא login) |

### API Routes חדשים

| Route | Method | תיאור |
|---|---|---|
| `/api/crm/signatures` | GET | רשימת בקשות (עם פילטר סטטוס) |
| `/api/crm/signatures` | POST | יצירת בקשה + שליחת WhatsApp + מייל |
| `/api/sign/[token]` | GET | שליפת מסמך לחתימה (ציבורי) |
| `/api/sign/[token]` | POST | קבלת חתימה → הטבעה → שמירה → התראה |

## תהליך עורך הדין

1. פתיחת תיק לקוח → כפתור **"✍️ שלח לחתימה"**
2. מודאל 3 שלבים:
   - **שלב 1** — העלאת PDF/Word (גרסה 1: העלאה ידנית; גרסה 2 עתידית: בחירה ממסמכי הסוכן AI)
   - **שלב 2** — סימון שדות חתימה: לחיצה על PDF → מוסיפה תיבה אמבר ניתנת לגרירה. סוגים: חתימה / תאריך / ראשי תיבות. מספר שדות בכל עמוד.
   - **שלב 3** — אישור פרטי לקוח (שם, טלפון, מייל מהתיק) + בחירת שליחה (וואטסאפ / מייל / שניהם)
3. לחיצה על "שלח" → מייצר טוקן UUID → שולח הודעה → מעדכן טיימליין התיק

**הודעת וואטסאפ ללקוח:**
> "שלום [שם], משרד עו"ד אוהד טבת שלח לך מסמך לחתימה דיגיטלית. לחץ לחתימה: tevet-law.com/sign/[טוקן] — הקישור תקף ל-30 יום."

## חוויית לקוח — `/sign/[token]`

דף ציבורי, RTL, mobile-first, ללא התחברות.

**מבנה:**
- Header: לוגו משרד + שם מסמך + "🔒 מאובטח"
- תצוגת PDF מלאה עם גלילה
- שדות חתימה מסומנים בצהוב/אמבר
- כפתור "חתום ואשר" גדול בתחתית (מופיע רק אחרי חתימה על כל השדות)

**מודאל חתימה (נפתח בלחיצה על שדה):**
1. שדה שם מלא (חובה)
2. canvas חתימה עם `perfect-freehand`:
   - קו בגוון כחול כהה (`#1a1a3e`) — לא שחור גס
   - וריאציית עובי: דק בהתחלה, מעט עבה באמצע, דק בסוף
   - SVG ולא bitmap — חד בכל צג
   - כפתור "נקה" לציור מחדש
3. Checkbox: "אני מאשר שקראתי את המסמך וחתמתי מרצוני החופשי"

**אחרי חתימה:** ספינר → מסך הצלחה ✅

**שגיאות מטופלות:**
- טוקן לא קיים → "הקישור אינו תקף"
- טוקן פג תוקף → "הקישור פג תוקף — פנה למשרד"
- כבר נחתם → "מסמך זה כבר נחתם"

## הטבעת PDF בשרת

כשהלקוח שולח חתימה, השרת:

1. מקבל: SVG חתימה + שם + IP + User-Agent + טוקן
2. טוען PDF מקורי מ-Supabase Storage
3. לכל שדה חתימה:
   - ממיר `%` → נקודות PDF: `x_pts = x% × pageWidth`, `y_pts = (1 - y%) × pageHeight`
   - מטביע תמונת SVG בשדה (ב-`pdf-lib`)
   - מוסיף טקסט קטן: *"נחתם ע"י [שם] — [תאריך] — [IP]"*
4. מוסיף עמוד audit trail בסוף:
   ```
   תעודת חתימה דיגיטלית
   ──────────────────────
   מסמך: [שם]
   חותם: [שם מלא]
   תאריך: [timestamp]
   IP: [ip]
   מכשיר: [device]
   Hash מקורי: [sha256]
   Hash חתום:  [sha256]
   ```
5. שומר PDF חתום → `signed-documents/[case_id]/[uuid].pdf`
6. מעדכן `signature_requests`: `status='signed'`, `signed_url`, `signed_at`
7. שולח התראות (ראה פרק הבא)

## נראות ומעקב לעורך הדין

### שכבה 1 — כרטיס דשבורד
כרטיס "✍️ ממתין לחתימה" עם מספר הבקשות הפתוחות. לחיצה → `/crm/signatures`.

### שכבה 2 — עמוד `/crm/signatures`
טבלה עם עמודות: לקוח / מסמך / נשלח / סטטוס / פעולות.

**צבעי סטטוס:**
- 🟡 `pending` — ממתין
- 🔴 `pending` + לא נפתח 7+ ימים — דחוף, שלח תזכורת
- ✅ `signed` — נחתם
- ⚫ `expired` — פג תוקף

**פעולות בכל שורה:** צפה ב-PDF / שלח תזכורת / ביטול

### שכבה 3 — פעמון + וואטסאפ בזמן אמת
כשנחתם:
- פעמון ב-CRM מהבהב עם badge
- הודעת וואטסאפ לעורך הדין: "✅ [שם לקוח] חתם על [מסמך]"

### בתיק עצמו
- טיימליין: "📨 נשלח לחתימה" → "✅ נחתם — [תאריך]"
- כפתור "הורד PDF חתום" (מופיע אחרי חתימה)
- תג "ממתין לחתימה" בראש התיק (כתום → נעלם אחרי חתימה)
