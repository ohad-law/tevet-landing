# רובוט פולואפ אוטומטי לוואטסאפ — משרד עו"ד טבת

תאריך: 2026-06-10
סטטוס: מאושר עקרונית, ממתין לאישור spec

## המטרה

ליד שנכנס מטופס מטא ולא ענה — מקבל סדרת הודעות פולואפ אוטומטיות בוואטסאפ
שמחממות אותו לקראת סגירה. אוהד הוא "וואן מאן שואו" ואין לו זמן לרדוף ידנית.
המערכת רודפת במקומו, ועוצרת ברגע שהליד מגיב או שאוהד מתחיל לטפל.

## כללים קבועים (חובה — לא לחרוג)

- **לעולם לא להעלות מודעה/קמפיין ל-ACTIVE** בלי אישור כתוב מאוהד. לא רלוונטי ישירות
  כאן, אבל הכלל נשמר בכל עבודה על הפרויקט.
- **המילה "חינם" אסורה לחלוטין** בכל הודעה — לתמיד, בלי יוצא מן הכלל.
- **המילה "תשלום" אסורה בהודעות** — תמחור נמסר רק בשיחה. מותר: "בדיקה ראשונית ללא עלות".
- כל ההודעות בעברית תקינה, טון אישי וישיר.

## אילוצים טכניים

- **Vercel Cron רץ פעם ביום** (תוכנית חינמית, `0 6 * * *`). הרצף שלנו יומי (+1/+3/+7),
  אז בדיקה יומית אחת מספיקה לחלוטין. אין צורך בתדירות גבוהה יותר ואין עלות נוספת.
- כבר קיים cron אחד (`poll-meta-leads`). נוסיף את לוגיקת הפולואפ כ-cron יומי שני.
- WhatsApp נשלח דרך Green API (instance קיים, מחובר כרגע למספר האישי של אוהד).
  מעבר ל-eSIM בעתיד = סריקת QR מחדש בלבד, בלי שינוי קוד.

## ארכיטקטורה

### 1. מעקב מצב פולואפ — שדות חדשים ב-Supabase

מיגרציה שמוסיפה לטבלאות `leads` ו-`leads_talush`:

| שדה | סוג | ברירת מחדל | תפקיד |
|------|-----|-------------|--------|
| `followup_stage` | int | 0 | כמה פולואפים נשלחו (0-3) |
| `followup_next_at` | timestamptz | null | מתי הפולואפ הבא מתוכנן |
| `followup_stopped` | boolean | false | נעצר (ענה / בטיפול / מקס) |
| `followup_opted_out` | boolean | false | ביקש להסיר |
| `last_followup_at` | timestamptz | null | מתי נשלח הפולואפ האחרון |

**תיקון נדרש באותה מיגרציה:** ה-CHECK constraint של `leads.status` מאפשר כרגע `'טופל'`,
אבל ה-CRM שולח `'בטיפול'` (כמו ב-`leads_talush`). זה באג קיים — שינוי סטטוס לליד כללי
נכשל בשקט. נעדכן את ה-constraint ל-`'בטיפול'` כדי שעצירת-הרובוט-בסטטוס תעבוד.

### 2. אתחול בעת כניסת ליד

ב-`/api/leads/incoming` (אחרי הודעת החימום הקיימת): מגדיר `followup_next_at = now + 1 יום`,
`followup_stage = 0`. לידים שמסוננים (פחות משנה) — לא נכנסים לרצף.

### 3. השעון — `/api/cron/followup-leads` (cron יומי)

מאומת ב-`CRON_SECRET` כמו ה-cron הקיים. כל הרצה:

1. שולף לידים מ-`leads` + `leads_talush` שעונים על **כל** התנאים:
   - `followup_stopped = false`
   - `followup_opted_out = false`
   - `followup_stage < 3`
   - `status = 'חדש'`
   - `followup_next_at <= now()`
2. תקרה יומית: עד `DAILY_CAP = 30` הודעות בהרצה (הגנה על המספר). מעבר לזה — נדחה למחר.
3. לכל ליד: בונה הודעה לפי `followup_stage + 1` והסיטואציה, שולח, ואז:
   - `stage 0→1`: שלח תזכורת עדינה, `next_at = now + 2 ימים` (יום 3)
   - `stage 1→2`: שלח ערך/הוכחה, `next_at = now + 4 ימים` (יום 7)
   - `stage 2→3`: שלח הזדמנות אחרונה, `followup_stopped = true` (מיצינו)
   - תמיד: `last_followup_at = now`

### 4. זיהוי תשובה — הרחבת `/api/webhooks/whatsapp-incoming`

ה-webhook הקיים כבר מזהה תשובה מליד ומודיע לאוהד. נוסיף:
- כשליד מוכר עונה → `followup_stopped = true` (הרובוט שותק מיד).
- בדיקה גם ב-`leads_talush` (כרגע בודק רק `leads` — פער קיים).
- מילת הסרה (`הסר` / `הפסק` / `stop`) → `followup_opted_out = true` + הודעת אישור הסרה.

### 5. עצירה ב"בטיפול" — הרחבת `PATCH /api/crm/leads/[id]`

כשהסטטוס משתנה מ-`'חדש'` לכל דבר אחר → `followup_stopped = true`.

### 6. התבניות — `lib/followup-templates.ts`

3 בוני-הודעה, מותאמים לסיטואציה (פוטר / התפטר / שכר), בסגנון של `buildLeadMessage` הקיים.
בלי "חינם", בלי "תשלום". כל הודעה כוללת קריאה עדינה לפעולה (שיחת 10 דק').

## בלמים (הגנה על המספר)

- **תקרה יומית** — קבוע `DAILY_CAP`, הרבה מעל קצב הלידים הנוכחי.
- **רק לידים מהטופס** — כל הלידים בטבלאות ביקשו ליצור קשר. לא קר.
- **קצב אנושי** — cron יומי + לולאה רגילה, לא הצפה.
- **opt-out** — מילת "הסר" עוצרת לתמיד.
- **עצירה מיידית** — תשובה או "בטיפול" עוצרים את הליד.

## סיכונים

1. **חסימת המספר האישי** — נמוך (לידים שביקשו קשר + בלמים), אבל לא אפס. מעבר ל-eSIM
   בעתיד מבטל את הסיכון.
2. **באג סטטוס `'טופל'` מול `'בטיפול'`** — נתקן במיגרציה. סיכון: אם יש לידים קיימים עם
   `'טופל'` נצטרך להמיר אותם. נבדוק לפני השינוי.
3. **Green API לא מחובר / מנותק** — אם הסשן נופל, הודעות לא יוצאות בשקט. נוסיף לוג ברור.

## מחוץ לתחום (שלב ב')

- שכבת AI שמתאימה הודעה לפי הערה חופשית שאוהד רושם בליד — נוסיף רק אם נראה צורך.
- מעבר למספר eSIM ייעודי — סריקת QR בלבד, בלי קוד.
- שיפורי דשבורד (מקור מדויק לכל ליד, הפרדה לפי תאריך) — מסמך נפרד.
